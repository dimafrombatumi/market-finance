# Настройка Supabase для Market Finance

Этот документ содержит инструкции по настройке Supabase для проекта Market Finance.

## 1. Создание проекта Supabase

1. Перейдите на [supabase.com](https://supabase.com)
2. Войдите в аккаунт или создайте новый
3. Нажмите "New Project"
4. Выберите организацию
5. Введите название проекта: `market-finance`
6. Выберите регион (рекомендуется ближайший к вашим пользователям)
7. Введите пароль для базы данных
8. Нажмите "Create new project"

## 2. Настройка базы данных

1. После создания проекта перейдите в раздел "SQL Editor"
2. Скопируйте содержимое файла `supabase-schema.sql`
3. Вставьте SQL код в редактор
4. Нажмите "Run" для выполнения

## 3. Получение ключей API

1. Перейдите в раздел "Settings" → "API"
2. Скопируйте следующие значения:
   - **Project URL** (например: `https://your-project.supabase.co`)
   - **anon public** ключ (начинается с `eyJ...`)

## 4. Настройка переменных окружения

1. Создайте файл `.env.local` в корне проекта
2. Добавьте следующие переменные:

```env
REACT_APP_SUPABASE_URL=https://your-project.supabase.co
REACT_APP_SUPABASE_ANON_KEY=your_anon_key_here
```

**Важно:** Замените `your-project` и `your_anon_key_here` на реальные значения из вашего проекта Supabase.

## 5. Настройка аутентификации (опционально)

Если вы хотите добавить аутентификацию пользователей:

1. Перейдите в раздел "Authentication" → "Settings"
2. Настройте провайдеры аутентификации (Email, Google, GitHub и т.д.)
3. Обновите политики RLS в базе данных при необходимости

## 6. Настройка Row Level Security (RLS)

По умолчанию в схеме включены базовые политики RLS. Для продакшена рекомендуется:

1. Перейти в раздел "Authentication" → "Policies"
2. Настроить более строгие политики доступа
3. Учесть роли пользователей (admin, manager, employee)

## 7. Мониторинг и аналитика

1. Перейдите в раздел "Logs" для мониторинга запросов
2. Используйте раздел "Analytics" для анализа производительности
3. Настройте алерты в разделе "Alerts"

## 8. Резервное копирование

1. Перейдите в раздел "Settings" → "Database"
2. Настройте автоматические бэкапы
3. Установите расписание для регулярных бэкапов

## 9. Проверка подключения

После настройки переменных окружения:

1. Запустите проект: `npm start`
2. Откройте браузер и перейдите на `http://localhost:3000`
3. Проверьте, что данные загружаются из Supabase
4. Откройте DevTools → Network для проверки запросов к API

## 10. Структура базы данных

### Таблицы:

- **products** - товары магазина
- **sales** - продажи
- **sale_items** - позиции в продажах (связующая таблица)
- **transactions** - транзакции (доходы/расходы)

### Ключевые особенности:

- Автоматическое создание транзакций при завершении продаж
- Автоматическое обновление остатков товаров
- Индексы для оптимизации производительности
- Триггеры для поддержания целостности данных

## 11. Troubleshooting

### Ошибка подключения:
- Проверьте правильность URL и ключа API
- Убедитесь, что проект Supabase активен
- Проверьте настройки CORS в Supabase

### Ошибки RLS:
- Убедитесь, что пользователь аутентифицирован
- Проверьте политики доступа в разделе Authentication → Policies

### Проблемы с производительностью:
- Проверьте индексы в базе данных
- Используйте пагинацию для больших таблиц
- Мониторьте запросы в разделе Logs

## 12. Дополнительные настройки

### Реалтайм подписки:
```typescript
// Подписка на изменения в таблице products
const subscription = supabase
  .channel('products')
  .on('postgres_changes', 
    { event: '*', schema: 'public', table: 'products' },
    (payload) => {
      console.log('Product changed:', payload);
      // Обновить состояние приложения
    }
  )
  .subscribe();
```

### Загрузка файлов:
```typescript
// Загрузка изображения продукта
const { data, error } = await supabase.storage
  .from('product-images')
  .upload(`${productId}/image.jpg`, file);
```

## 13. Безопасность

- Никогда не коммитьте файл `.env.local` в Git
- Используйте разные ключи для разработки и продакшена
- Регулярно обновляйте пароли и ключи API
- Настройте мониторинг подозрительной активности

## 14. Масштабирование

- Используйте connection pooling для высоких нагрузок
- Настройте read replicas для аналитических запросов
- Рассмотрите использование Edge Functions для сложной логики
- Мониторьте использование ресурсов и оптимизируйте запросы
